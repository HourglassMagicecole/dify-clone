# 요구사항

## 기능 요구사항

### Agent 관리 관련 요구사항

**FR1**: 시스템은 교육 참가자가 순차적으로 Agent를 구성할 수 있도록 5단계 가이드형 워크플로우를 제공해야 합니다:
- 1단계: 기본 설정 (Agent 이름 및 설명 입력, 대화형/작업형 유형 선택, 역할 정의)
- 2단계: 프롬프트 구성 (시스템 프롬프트 작성 with 템플릿, 변수 정의 및 설정, Few-shot 예제 추가, 실시간 프롬프트 미리보기)
- 3단계: LLM 설정 (OpenAI/Anthropic/Google 제공자 선택, GPT-4o/Claude-Sonnet/Gemini 등 모델 선택, Temperature/Max Tokens/Top-p 파라미터 조정, 멀티모달 활성화)
- 4단계: Tool/RAG 구성 (웹 검색, 계산기, 날씨 API, OCR, 이미지 생성, TTS, STT 등 내장 도구 선택, 외부 API 연동, RAG 지식베이스 연결)
- 5단계: 확인 및 테스트 (전체 구성 요약 확인, 테스트 채팅 실행, 최종 저장 및 배포)

**FR2**: Agent 관리 기능으로 편집(모든 설정 수정), 복제(템플릿으로 활용), 삭제, 읽기 전용 공유를 지원해야 합니다.

### Workflow 관련 요구사항

**FR3**: 드래그 앤 드롭 방식의 비주얼 Workflow 편집기는 다음 11가지 노드 유형을 지원해야 합니다:
- 시작/종료 노드 (Workflow의 시작과 끝 정의)
- 입력 노드 (텍스트, 파일, 이미지 입력)
- 출력 노드 (텍스트, 파일, 이미지 출력)
- 변수 노드 (데이터 저장 및 변환)
- LLM 노드 (언어 모델 호출 및 프롬프트 처리)
- 조건 분기 노드 (IF/ELSE 로직 구현)
- 반복 노드 (리스트 처리 및 반복 작업)
- 도구 실행 노드 (외부 API 또는 내장 도구 호출)
- RAG 검색 노드 (지식베이스 쿼리)
- HTTP 요청 노드 (외부 서비스 연동)
- Agent 호출 노드 (다른 작업형 Agent 연동)

**FR4**: Workflow는 변경 이력 자동 저장, 삭제, 복제, 읽기 전용 공유 기능을 제공해야 합니다.

### RAG 시스템 요구사항

**FR5**: RAG 파이프라인 학습 인터페이스는 각 단계를 시각화하여 동작 원리를 이해할 수 있도록 해야 합니다:
- Load: TXT/Markdown/PDF 형식 지원, 파일 업로드 인터페이스, 메타데이터 자동 추출
- Split: 청킹 전략 선택(고정 크기/문장 단위/의미 단위), 20-5000 토큰 크기 조정, 오버랩 설정, 분할 결과 시각화
- Embed: OpenAI/Cohere 임베딩 모델 선택, 벡터 차원 표시, 임베딩 생성 진행률 표시
- Store: 저장된 청크 수 및 용량 표시, 인덱스 관리 인터페이스

**FR6**: RAG 검색 테스트 시 쿼리 입력 후 관련 청크 검색, 유사도 점수 표시, 핵심 부분 하이라이팅, 리랭킹 기능을 제공해야 합니다.

**FR7**: RAG 관리 기능으로 문서 목록 및 삭제, 임베딩 재생성, 스토리지 모니터링을 제공해야 합니다.

### Agent 실행 인터페이스 요구사항

**FR8**: 대화형 Agent 인터페이스는 다음 기능을 제공해야 합니다:
- 실시간 채팅 및 스트리밍 응답
- 멀티모달 입력 (텍스트, 이미지, 파일 업로드)
- 처리 단계 표시 (실행 중인 도구 또는 참조 중인 RAG 표시)
- 중간 결과 및 각 단계별 처리 결과 확인
- 실시간 토큰 사용량 및 비용 계산
- 각 구성 요소별 응답 시간 측정
- 대화 내보내기 (텍스트, JSON 형식)
- 응답 재생성 기능
- 대화 기록 관리 및 이전 대화 재접속
- 처리 완료 시 시각적/음성 알림

**FR9**: 작업형 Agent 인터페이스는 다음 기능을 제공해야 합니다:
- 사전 정의된 필드로 구성된 폼 기반 입력
- 다양한 파일 형식 업로드 지원
- 작업 진행 상태 표시 (대기, 처리 중, 완료, 오류)
- 처리 단계 및 중간 결과 표시
- 실패 시 작업 재시도 옵션
- 작업 내역 조회 및 재실행

### Workflow 실행 인터페이스 요구사항

**FR10**: Workflow 실행 인터페이스는 다음을 제공해야 합니다:
- 실행 시 입력 폼 제공 (텍스트, 파일, 이미지)
- 실행 제어 버튼 (시작/중지)
- 실행 상태 표시 (대기, 실행 중, 완료, 오류)
- 각 노드별 처리 상태, 순서 및 시간 표시
- 최종 결과 출력
- 실행 내역 조회 및 재실행 기능
- 실시간 토큰 사용량 및 비용 계산

### 사용자 대시보드 요구사항

**FR11**: 사용자 대시보드는 다음 정보를 표시해야 합니다:
- 생성된 Agent/Workflow/RAG 개수 및 상태 요약
- 최근 활동 (생성/수정된 리소스 및 실행 기록)
- API 호출 횟수, 토큰 사용량, 비용 요약
- 사용자가 생성한 리소스 목록
- 프로필 수정 및 비밀번호 변경 기능

### 관리자 기능 요구사항

**FR12**: 사용자 관리 기능:
- 계정 생성, 정보 수정 및 삭제
- 비밀번호 초기화, 계정 잠금/해제, 권한 변경
- CSV 파일로 다수 계정 일괄 생성
- 교육 세션 관리, 세션별 권한 설정
- 그룹/계정별 활동 로그 조회 및 필터링
- 사용자/세션별 생성 자료 및 파일 일괄 삭제

**FR13**: 교육 자료 관리:
- 수업용 샘플 Agent/Workflow 생성, 수정, 삭제, 공유
- 템플릿 라이브러리 관리

**FR14**: API 및 모니터링:
- API Key 중앙 관리 (상용 LLM 및 외부 API)
- 사용자별/세션별 사용량 제한 설정
- 실시간 접속자 수 및 활성 세션 모니터링
- API별/사용자별/세션별 사용 통계
- 오류 로그 및 시스템 상태 모니터링

## 비기능 요구사항

**NFR1**: 최대 50명 동시 접속 및 작업 가능, 50개 동시 LLM 요청 처리

**NFR2**: 일반 작업 3초 이내, LLM 호출 30초 이내 응답 (90 percentile)

**NFR3**: 페이지 로딩 시간 3초 이내 달성률 95%

**NFR4**: 사용자당 1GB 파일 저장 공간 지원

**NFR5**: 교육 시간 중 99% 이상 가용성 보장

**NFR6**: 한국어/영어 다국어 인터페이스 지원

**NFR7**: Chrome 100+, Firefox 100+, Safari 15+, Edge 100+ 브라우저 호환

**NFR8**: 최소 1280x720, 권장 1920x1080 해상도 지원

**NFR9**: 150% 화면 확대 시에도 레이아웃 깨짐 없이 지원

**NFR10**: 최소 1Mbps, 권장 10Mbps 네트워크 환경

## UX 요구사항

**UXR1**: 기술 용어 최소화, 아이콘과 툴팁을 활용한 직관적 인터페이스

**UXR2**: 각 기능에 대한 인터랙티브 튜토리얼 제공

**UXR3**: 모든 작업에 대한 시각적 피드백 제공

**UXR4**: 노트북에 최적화된 반응형 레이아웃

**UXR5**: 용도별 사전 구성된 Agent/Workflow 샘플 라이브러리 제공

**UXR6**: 각 기능/설정/도구/파라미터에 대한 상세 도움말 시스템

## 호환성 요구사항

**CR1**: 기존 Dify 백엔드 API와 완벽하게 호환되어야 합니다.

**CR2**: 기존 데이터베이스 스키마를 그대로 사용하되 교육용 확장 테이블만 추가합니다. (단일 테넌트 유지)

**CR3**: 교육용 UI는 독립적이지만 Dify 코어 기능은 모두 활용 가능해야 합니다.

**CR4**: 기존 LLM 제공자 통합 및 도구들을 그대로 사용할 수 있어야 합니다.

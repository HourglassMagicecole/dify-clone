# 기술 제약사항 및 통합 요구사항

## 기존 기술 스택

**언어**: Python 3.11-3.13 (백엔드), TypeScript (프론트엔드)
**프레임워크**: Flask 3.1.2 (백엔드), Next.js 15 + React 19 (프론트엔드)
**데이터베이스**: PostgreSQL (최신)
**인프라**: Docker Compose, Redis (Celery 브로커)
**외부 종속성**: OpenAI, Anthropic, Google AI APIs

## 통합 접근법

**데이터베이스 통합 전략**:
- 기존 Dify 스키마 유지
- 교육 관리용 확장 테이블 추가 (education_sessions, resource_tags, learning_progress)
- Flask-Migrate를 통한 마이그레이션 관리

**API 통합 전략**:
- Dify 백엔드 API 엔드포인트 100% 재사용
- 교육 전용 엔드포인트 추가 (/edu/api/*)
- JWT 기반 인증 확장 (그룹 권한 추가)

**프론트엔드 통합 전략**:
- 완전히 새로운 Next.js 앱 생성 (web-edu/)
- Dify API 클라이언트 라이브러리 재사용
- 교육 특화 UI 컴포넌트 라이브러리 구축

**테스팅 통합 전략**:
- 기존 백엔드 pytest 테스트 스위트 확장
- 프론트엔드 Jest 및 Playwright E2E 테스트
- 교육 시나리오별 통합 테스트

## 코드 구성 및 표준

**파일 구조 접근법**:
```
web-edu/                 # 새로운 교육용 프론트엔드
├── app/                 # Next.js 15 App Router
│   ├── (education)/    # 교육 참가자 라우트
│   ├── (admin)/        # 관리자 라우트
│   └── components/     # 공유 컴포넌트
├── features/           # 기능별 모듈
│   ├── agent-builder/  # 5단계 Agent 빌더
│   ├── workflow-editor/# 비주얼 편집기
│   └── rag-visualizer/ # RAG 시각화
├── i18n/               # 국제화 (한국어/영어)
└── service/            # API 클라이언트
```

**네이밍 컨벤션**: PascalCase 컴포넌트, kebab-case 파일명, camelCase CSS 모듈
**코딩 표준**: TypeScript strict 모드, ESLint + Prettier, React Hook 규칙
**문서화 표준**: JSDoc 코멘트, Storybook 컴포넌트 문서, OpenAPI 명세

## 배포 및 운영

**빌드 프로세스 통합**: 멀티스테이지 Docker 빌드, pnpm workspace 의존성 관리
**배포 전략**: Blue-Green 배포, 무중단 배포, 자동 롤백 메커니즘
**모니터링 및 로깅**: 교육 세션별 로그 분리, 실시간 메트릭, 오류 알림
**구성 관리**: 환경별 설정, 교육장별 커스터마이징, Feature 플래그

## 위험 평가 및 완화

**기술적 위험**:
- Dify API 변경 시 호환성 → API 버전 관리 및 어댑터 패턴
- 동시 50명 접속 성능 → 로드 밸런싱 및 캐싱 전략

**통합 위험**:
- 백엔드 API 변경 영향 → API 계약 테스트 자동화
- 데이터베이스 스키마 충돌 → 네임스페이스 분리

**배포 위험**:
- 교육 중 시스템 장애 → 백업 서버 및 재시도 메커니즘
- 버전 업데이트 실패 → 자동 롤백 메커니즘

**완화 전략**:
- 단계별 개발 및 테스트
- 파일럿 교육 세션 운영
- 24시간 핫픽스 대응 체계
- 모든 중요 작업 및 오류 상세 로깅

## 롤백 전략 (rollback-procedures.md 기반)

### 롤백 원칙
1. **독립적 프론트엔드**: web-edu는 기존 시스템과 독립적으로 롤백 가능
2. **데이터베이스 보호**: 교육용 테이블만 영향을 받도록 격리
3. **무중단 롤백**: Blue-Green 배포로 서비스 중단 최소화
4. **Feature 플래그**: 기능별 활성화/비활성화 제어

### Feature 플래그 시스템
```typescript
// web-edu/config/features.ts
export const FEATURES = {
  AGENT_WIZARD: process.env.NEXT_PUBLIC_FEATURE_AGENT_WIZARD === 'true',
  WORKFLOW_EDITOR: process.env.NEXT_PUBLIC_FEATURE_WORKFLOW_EDITOR === 'true',
  RAG_VISUALIZER: process.env.NEXT_PUBLIC_FEATURE_RAG_VISUALIZER === 'true',
  ADMIN_DASHBOARD: process.env.NEXT_PUBLIC_FEATURE_ADMIN_DASHBOARD === 'true',
}
```

### 자동 롤백 시스템
- **헬스체크 기반**: Docker healthcheck로 자동 재시작
- **메트릭 기반**: 오류율 5%, 응답시간 3초, 가용성 95% 임계값
- **점진적 재배포**: Canary 배포로 10% 트래픽부터 시작
